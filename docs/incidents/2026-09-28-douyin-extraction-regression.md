# 抖音提取回归与 1.3.169 现场复验失败

日期：2026-09-28。状态：未解决，继续调查。责任范围：插件媒体获取及验收覆盖。

## 用户影响
匿名或已登录用户都可能拿不到目标视频，无法进入转写。1.3.169 用户复验仍失败，不能将此版标为抖音稳定版。ASR/OCR 组件显示可用不代表视频获取成功；末路 yt-dlp 的 Cookie refresh 提示不是所有失败路径的共同根因证明。

## 已确认时间线
- 1.3.152：网络监听设置不阻塞页面导航；只确认为历史时序对照，不具备本次用户全文转写验收，不标记为稳定基线。
- 1.3.153，7f46ebd8：导航前等待 Network.enable，引入可能互相等待的问题。
- 1.3.165，84e98967：短超时后 detach，失去网络媒体捕获。
- 1.3.169，d41d46dd9a8adf865316907727c82a2c48242ded，PR #141：修复上述时序、保留监听，精确媒体就绪后不被 DOM 超时丢弃，空结果标记失败。
- 1.3.169 发布资产与 Git 身份验证通过，但用户随后报告依然失败：Electron39.8.3，debugger ready、页面200、responseReads/Bytes/dropped/blockedMedia均0，两轮约27秒无媒体。

## 验收缺口与责任
上次原生 Electron 实测在主进程直接加载插件，伪造 remote 指向主进程对象，并直接输入标准视频长链，跳过真实渲染进程跨进程调用和分享短链入口。该实测的有效 MP4 首片结果是真实的，但证明范围不足以认定 Obsidian 用户链路已恢复；没有完成全文 ASR 与用户现场验收。作者和独立审查均未充分识别此覆盖缺口。

本次官方 @electron/remote 2.1.3 + Electron39.8.3 的隔离渲染进程对照，匿名长链约5秒取得46个媒体地址、读取13项响应；证明该桥接在本机该条件下能正常工作，不能据此反推用户 Cookie 有问题。其他路由/浏览器标识试验仍出现0候选和探测超时，尚未分离环境波动。

## 诊断边界
responseReads只在响应被筛选且loadingFinished配对后开始计数。0不代表完全没有CDP事件，也不代表登录失效。需要分别检验事件送达、候选筛选、完成配对、正文读取、页面运行时状态。诊断默认只记录计数、错误枚举和布尔状态，不保存Cookie、原始链接、标题、正文、用户路径或堆栈。

## 后续确定缺口：后台定时器节流

提取窗口启用后台节流，页面中的连续定时任务可能被延后至提取预算之外。真实remote本地HTTPS fixture只在40次100ms定时器后发出目标媒体请求：不可变1.3.169读不到媒体并失败；候选在专属窗口导航前关闭后台节流后，同一fixture取得目标媒体。空HTML200、错误作品仍失败，窗口回收检查通过。此用例只使用合成数据，不访问抖音，不依赖登录账号。

线上匿名对照：关闭节流三次均取得媒体（约5.1–5.5秒）；基线同条件仍有成功与超时混合结果。因此修复已证明的定时器缺口，但不能将其称为用户现场唯一根因。显式隐藏窗口仍可能令document.hidden或requestAnimationFrame不可用；此处不承诺改变这些网页行为，也不伪造页面可见性。

候选另外增加原始CDP消息、响应、文档响应、完成和失败事件计数，结束时一次写入，区分“无事件”和“事件有但正文未读取”。没有扩大响应正文读取范围，没有保留URL、Header或用户内容。
