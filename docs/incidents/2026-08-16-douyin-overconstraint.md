# 2026-08-16 抖音媒体提取过度约束复盘

## 事实

- 未发现“用户请求作品 A，插件实际转写推荐作品 B”的真实线上事故。
- 推荐流限制来自开发注释、合成测试和风险推测。
- 真实失败样本里页面已经存在可播放媒体，但代码因混合身份、候选身份不精确、多个无身份播放器或缺少稳定 aweme ID 返回空。
- `1.3.30` 先取精确详情，失败后直接使用页面媒体，没有这些失败门槛。

## 根因与纠正

诊断信息被逐步升级成产品阻断条件，保护了未发生的风险，却制造高频真实失败。精确通道继续优先；浏览器兜底恢复当前页面主播放器选择，身份只参与排序；仅最终地址明确是另一具体作品时拒绝。

以后新增提取阻断必须先提供真实事故、脱敏复现样本和历史可用对照。没有证据时，只允许记录诊断、降低增强能力或进入备用路径。

## 防复发测试

- 混合页面/候选身份仍选择可见播放主媒体。
- 多个无身份播放器按播放状态、可见性、面积和 DOM 顺序选择。
- 缺少稳定 aweme ID 仍进入非严格浏览器兜底。
- 最终地址明确跳到另一个 `/video/:id` 时仍拒绝。
