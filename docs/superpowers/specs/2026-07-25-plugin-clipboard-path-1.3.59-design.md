# 插件 1.3.59：剪切板链接兼容与保存路径规范化设计

## 背景

1.3.58 的小红书失败诊断确认，一部分用户通过“读取剪切板”保存分享口令时，记录会以 `text` 类型进入插件；插件只对 `link` 或 `webpage` 执行网页提取，因此即使正文包含可用链接，也会被原样写成文本笔记。

另有 Windows 用户把保存目录设置为二级路径后，在 Obsidian 中看到两个同名目录，删除其中一处另一处也消失。代码复现显示，实际写入可能混用 `raw\wechatmd` 与 `raw/wechatmd`。两者在 Windows 指向同一物理目录，但 Obsidian 可按不同字符串建立两个缓存项。

## 目标行为

### 剪切板文本中的链接

- 对 `text` 记录提取 HTTP(S) URL 候选。
- 只有选择结果明确且地址可安全访问时，才在内存中把该记录副本提升为 `webpage` 进入现有提取链。
- 原始整段文本保存在 `metadata.shareText`，云端原记录不修改。
- 单一公开 HTTP(S) 链接允许自动提取，覆盖小红书、微信公众号、飞书、抖音、B 站、小宇宙和普通网页。
- 如果文本中存在多个 URL：
  - 仅有一个属于现有受支持平台时，选择该平台 URL；
  - 存在多个受支持平台 URL，或只有多个普通 URL 时，保持 `text`，避免猜测。
- `localhost`、回环、链路本地、私网、保留地址、带用户名密码的 URL、非 HTTP(S) scheme 均不得自动访问。
- 网页提取失败继续使用 1.3.58 的失败关闭和诊断机制，不生成伪成功笔记。

### 保存目录

- 设置加载与保存时把 `\` 统一为 `/`，压缩重复分隔符，并移除首尾分隔符。
- 拒绝盘符、绝对路径、`.`、`..` 和空段等不安全路径；无效配置回退到安全默认目录。
- 如果规范路径与旧设置不同，插件启动后持久化迁移后的设置。
- `ensureFolder` 按路径段逐级检查：已存在直接复用，缺失才创建。
- 普通笔记、日期子目录、视频号捕获、图片、附件和二进制写入前再次规范化。
- 不移动、复制、合并或删除现有用户文件。

## 兼容性

- 已经是 `webpage` 的记录不变。
- 已经是 `link` 的支持平台提取逻辑不变。
- 不含链接的 `text` 记录不变。
- 标题、原始分享文案、来源 URL、记录 ID 和失败重试语义保持不变。
- 本次只发布插件，不修改或部署当前有并行改动的小程序与云函数。

## 防回退测试

- `text` + 单一小红书短链、普通网页链接：提升为网页并保留原文。
- `text` + 纯文字、多普通链接、多平台链接、私网/本机/带凭据地址：保持文本且不发起请求。
- `text` + 多链接但仅一个受支持平台：选择受支持平台链接。
- 1.3.58 的小红书失败关闭、视频号提示和普通网页行为继续通过。
- `raw\wechatmd` 迁移并写为 `raw/wechatmd`。
- 已存在规范目录不调用 `createFolder`；缺失嵌套目录逐级创建。
- 普通笔记、日期目录、视频号、图片和附件的最终 adapter 路径都只含 `/`。

## 发布与回退

版本为 1.3.59。通过受保护分支合并后，以最终 `main` SHA 创建 annotated tag，等待正式 Release 五项资产生成并验证。回退方式为停止推广并发布新的补丁版本；不覆盖 tag 或 Release。
