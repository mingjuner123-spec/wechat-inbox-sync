# 社媒内容上下文渲染拆分设计

## 目标

把社媒笔记在转写前后展示的标题、正文、标签、封面和数据属性，从插件巨型入口文件中抽成单一、可测试的渲染模块。以后调整笔记格式时，不需要触碰登录、短链解析、浏览器抓取或本地转写链路。

## 不在本次范围内

- 不修改抖音、小红书、B 站、小宇宙的登录、短链跳转、页面抓取、媒体下载或转写策略。
- 不修改云函数、小程序、用户绑定配置或发布版本。
- 不改变已经约定的笔记输出顺序：标题、正文、标签、封面、视频文案转写、评论区。

## 方案

新增 `obsidian-plugin/wechat-inbox-sync/src/social-media-context-utils.js`，只暴露纯函数：

- 规范化标题、正文、标签和封面 URL；
- 过滤空值、重复标签和明显占位封面；
- 生成固定顺序的社媒原文上下文 Markdown；
- 为调用方返回可用于 YAML 属性的稳定元数据字段。

`src/main.js` 继续负责各平台页面解析和媒体地址选择，只把已解析出的普通数据传给该模块。主流程不再自行拼接社媒标题/正文/标签/封面的 Markdown。

## 兼容性

- 输出标题、正文、标签、封面与当前行为等价；仅消除重复和不稳定的空值格式。
- 小红书视频的评论区排序不由新模块产生，仍在现有转写结果拼装层保持在视频文案之后。
- 抖音严格浏览器媒体回退与本次渲染拆分完全隔离，只在没有任何可用媒体地址时使用。

## 验收

1. 对同一份已解析社媒数据，新模块输出的 Markdown 区块顺序固定为：标题、原文正文、标签、封面。
2. 重复标签、空 URL、无效封面不会生成重复或空区块。
3. 小红书、抖音、B 站、小宇宙的既有社媒上下文回归仍通过。
4. 抖音“公开页/详情/会话均无媒体时的严格浏览器回退”回归仍通过。
5. 插件 bundle 与源码一致，且不含未打包的相对依赖。

## 回退

本次仅新增纯模块并替换内部调用点。若发现输出格式回归，可只回退这一提交；媒体抓取、登录、云端和用户 `data.json` 均不受影响。
