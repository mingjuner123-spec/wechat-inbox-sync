# 抖音持久登录会话设计

## 目标

让首次使用插件的用户可在插件内完成一次抖音网页登录；后续抖音短链解析和转写复用该会话，以降低匿名请求触发验证页或空壳页面导致的失败率。

## 方案选择

采用插件独立的 Electron 持久 Session。它不读取 Chrome、Edge 或手机抖音的 Cookie，不上传 Cookie，也不写入插件 `data.json`。用户的常用浏览器登录与插件会话互不覆盖；抖音自行使登录令牌过期或撤销时，插件才提示重新登录。

## 行为

- 设置页新增“登录抖音转写”面板，显示“未登录 / 已登录 / 需要重新登录”。
- “打开抖音登录”只打开一个可见的插件会话窗口；用户自行完成扫码或账号登录，关闭窗口后插件只检查必要 Cookie 名称是否存在。
- “退出抖音登录”只清除这个插件独立分区的 Cookie，并要求用户确认；不会影响系统浏览器或其他平台登录。
- 抖音短链解析、详情接口和隐藏浏览器都使用同一个独立会话。匿名空壳或验证页仍会保留既有兜底；存在登录态时重试会自动带上该会话。
- 同一时刻只允许一个抖音隐藏浏览器任务，以免共享 Electron `webRequest` 监听器互相覆盖、造成批量同步必须重启。
- 隐藏解析窗口禁止创建所有子窗口，避免抖音页面的 `window.open` 露出播放器。

## 诊断与边界

诊断只记录登录状态布尔值、页面是否有验证特征、阶段和安全错误代码；不记录 Cookie、媒体 URL 或页面内容。抖音的网页风控不能被插件绕过：若登录态仍被验证，提示用户在插件内重新登录后再同步。

## 验收

1. 抖音 Session 与微信/小红书 Session 分区不同且持久。
2. 登录状态只依赖插件抖音分区；普通浏览器 Cookie 不参与读取。
3. 抖音详情与隐藏浏览器使用同一 Session；并发渲染按顺序执行。
4. 隐藏解析页不允许弹出可见子窗口。
5. 单元测试覆盖 Cookie 状态判断、会话选择、锁、无敏感诊断和当前抖音回归。
