# 抖音本地解析与登录兜底设计

## 目标

解决抖音近期对新设备和匿名访问加强风控后，音视频地址无法解析、无法转写的问题；不增加正常用户的操作。

## 用户规则

1. 所有抖音链接先走现有解析链路；成功时不显示登录提示。
2. 只有诊断明确命中抖音验证页、会话过期或解析器失效时，才提示用户在插件内登录抖音后重试。
3. 插件内抖音会话与系统浏览器隔离；浏览器登录、退出和账号切换不影响插件会话。
4. 媒体解析失败时，仍保留链接、标题和可取得的文案，避免整条记录丢失。

## 本地解析组件

插件安装独立的 yt-dlp 本地组件，媒体解析和 Cookie 使用均留在用户电脑：

- Windows 与 macOS 分别获取对应二进制；
- 插件只向 yt-dlp 提供自身抖音会话导出的临时 Cookie，不读取 Chrome、Edge、手机或其他应用的 Cookie；
- 临时 Cookie 文件使用后立即删除；
- yt-dlp 成功时作为优先媒体解析结果；失败时继续使用既有匿名/页面解析兜底。

## 更新策略

1. 组件初次缺失时安装。
2. 本地组件的版本检查缓存期固定为 48 小时。
3. 解析失败且错误明确指向 yt-dlp 解析器过期时，可忽略缓存额外检查一次；Cookie/登录失效不得触发反复下载更新。
4. 下载在临时路径完成，验证 SHA-256 后原子替换；失败继续使用原组件。

## 分发策略

解析不经过云端。CDN 只分发官方 yt-dlp 二进制和只读清单：

1. GitHub Actions 定时读取 yt-dlp 官方 Release；
2. 下载指定平台资产并校验官方哈希；
3. 上传不可变的版本目录；
4. 所有资产成功后最后发布 `latest.json`；
5. 用户插件只从国内 CDN 拉取清单和文件；GitHub 仅是开发/镜像同步侧的上游，不要求终端用户开梯子。

该镜像任务需要 GitHub Secrets 与 CDN 写入权限，属于单独的 L3 外部动作，不能在本地开发阶段自动执行。

## 失败与诊断

- `DOUYIN_CHALLENGE`：提示插件内登录；
- yt-dlp 版本/提取器错误：记录本机组件版本、清单版本、上次检查时间、下载来源与失败摘要；
- 下载或哈希失败：保留旧版，记录网络/哈希原因；
- 不记录或上传 Cookie、令牌和媒体内容。

## 验证

- 单元测试：48 小时检查缓存、强制检查条件、哈希不一致不替换、Cookie 临时文件清理、挑战页才提示登录；
- 集成测试：本地组件失败能回退现有解析；
- 平台测试：Windows x64、macOS arm64；
- 发布前：组件 CDN 清单、镜像任务与插件包版本身份分别验证。
