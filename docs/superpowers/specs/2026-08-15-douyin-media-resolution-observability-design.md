# 抖音媒体解析完整诊断与稳定降级设计

## 目标

在保持“绝不把推荐流视频误认为目标作品”的前提下，让抖音作品从链接解析、作品身份确认、媒体候选选择、下载刷新到本地转写的每一步都可观测、可回归、可定位。当前已确认的页面跳转后作品 ID 丢失问题必须修复；未来平台返回变化时，用户复制一次诊断即可明确失败阶段。

本批次同时保留已完成的飞书图片修复：附件写入后，Markdown 必须真实替换为本地附件引用才算成功。

## 不在范围内

- 不建设云端集中式抖音解析服务。
- 不保存 Cookie、媒体完整 URL、用户身份或其他敏感数据到诊断。
- 不放宽目标作品身份约束，不扫描并猜测推荐流视频。
- 不修改 CloudBase、绑定码、Pro、支付、小程序或用户数据。

## 统一解析流水线

每条抖音记录使用同一顺序：

1. `mobile-share`：匿名移动分享页，提取目标作品结构化信息与媒体地址。
2. `aweme-detail`：作品详情接口，响应中的 aweme ID 必须等于目标 ID。
3. `authenticated-session`：复用当前桌面会话，仍要求目标 ID 精确匹配。
4. `targeted-browser`：隐藏浏览器加载目标作品。精确绑定目标 ID 的播放器优先；页面唯一指向目标作品时，只允许恰好一个无身份、正在播放、可见且位于视口内的播放器。
5. `media-download`：候选按可靠性排序下载。403、过期或空响应只触发一次同身份刷新，不跨作品寻找其他媒体。
6. `local-transcription`：只有下载成功后进入 ASR；保存原始视频开关只控制是否额外保留媒体文件，不参与能否转写的判断。

任一阶段成功后可以继续补齐标题、正文、标签、封面和数据属性，但媒体身份不能被低可信阶段覆盖。

## 诊断合同

成功与失败都生成同一份脱敏摘要：

- 记录 ID 的短指纹和目标作品 ID 的短指纹。
- 原始链接类型：短链、`/video/:id`、`modal_id` 或其他。
- 每个阶段的 `attempted`、`ok`、`status/code`、`detailFound`、`mediaCount`、`identityOutcome`、`rejectionReason` 和耗时。
- 最终选中通道、候选序号、媒体类型、主机类别及是否刷新；不保存完整媒体 URL、Cookie、Authorization 或用户身份。
- 下载结果：HTTP 状态、内容类型、响应字节范围、是否过期刷新。
- 最终结果：进入 ASR、身份拒绝、无媒体、下载失败、取消或超时。

复制诊断信息时不再只显示“音视频转写失败”，而是显示最终原因和阶段摘要。成功日志只保留最近一次抖音解析摘要，避免无限增长；失败日志继续保留最近失败。

## 身份与安全边界

- 精确 debugger/detail 数据优先级最高。
- final/canonical 明确包含其他作品 ID 时立即拒绝。
- DOM 播放器携带目标 ID 且不含冲突 ID 时可接受。
- 仅靠页面唯一目标 ID 时，多个无身份可见播放器一律拒绝。
- 推荐流、预加载、广告、直播和无目标身份候选不得进入下载。
- 诊断只记录枚举、数量、状态和脱敏指纹。

## 去重与重复转写

历史已同步的抖音音视频不得阻止新上传记录再次转写；同一同步批次内的重复记录仍去重。已有本地笔记也不得阻止新的音视频记录写出。该规则必须通过既有重复转写回归测试。

## 测试矩阵

- 四个解析阶段分别成功并记录正确 `selectedStage`。
- final/canonical 丢失作品 ID，但 DOM 精确目标播放器存在。
- 页面唯一目标 ID 且只有一个可见播放候选。
- 多个无身份播放器、冲突作品 ID、推荐流候选全部拒绝。
- 详情接口空壳、超时、403、地址过期刷新、下载内容类型错误。
- 保存原始媒体开关开/关均可进入转写。
- 历史已同步记录再次上传仍进入转写；同批重复仍去重。
- Windows/macOS 的插件核心、社媒上下文、市场包、构建身份和发布治理回归。
- 飞书 token 下载后 Markdown 本地附件引用实际存在；URL HTML 转义不影响替换；附件写入但引用未命中必须告警。

## 发布门禁

1. 所有定向与完整回归通过。
2. 源码与生成 bundle 一致。
3. 独立审查 P0/P1/P2 均为 0。
4. 基于远端最新正式版本递增，不覆盖已有 tag 或 Release。
5. 发布候选、根镜像、manifest、versions、ZIP 与 Release 资产身份完全一致。
6. PR 门禁通过后合并，再创建不可变 annotated tag 和 Release；发布后回读 GitHub 与 Obsidian 可安装资产。

## 回退

如发布前验证失败，停在隔离分支，不影响线上 1.3.87。如发布后发现新回归，只发布更高版本修复，不移动或覆盖既有标签和 Release。
