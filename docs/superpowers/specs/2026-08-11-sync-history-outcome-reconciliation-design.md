# History 同步结果证据与中断补报设计

## 背景

当前插件已经能把明确的解析、转写、写入异常回传为 History 失败，但仍有三类假成功或漏报：网页返回空正文/新型壳页、本地旧失败占位文件触发去重成功、插件中断或失败状态接口暂时不可用。

用户于 2026-08-11 确认直接补齐并与现有候选一起替换。本设计仅修改插件本地候选，不部署云函数，也不建立上传失败尝试账本。

## 目标

1. 同步成功必须存在可交付内容证据。
2. 本地去重只接受可交付的旧笔记，失败收据和空壳笔记不能直接标记成功。
3. 已取得云端 attemptId 的处理中断、失败补报失败和完成补报失败，在下一次插件运行时可恢复上报。
4. 恢复信息最小化，不保存正文、URL、本地路径或原始异常。

## 非目标

- 不记录尚未成功写入 `inbox_records` 的上传尝试。
- 不通过语义模型判断文章质量，不保证识别所有未来反爬文案。
- 不更改小程序、云函数、数据库索引或线上环境。
- 不把历史上已经清理掉原始内容的成功记录自动改回失败。

## 方案选择

采用“结果证据门禁 + 本地恢复队列”。

未采用仅继续扩展错误关键词的方案，因为它无法覆盖空正文和进程中断；未采用云端心跳/任务队列方案，因为它需要新的部署、定时任务与维护成本。

## 结果证据门禁

### 网页

以下任一条件成立才允许成功：

- 存在非壳页的有效正文；
- 存在非空转写；
- 对明确支持图片内容交付的记录，存在已保存的本地图片正文证据。

空正文、只有 URL、登录/App 引导、验证码、付费墙、访问限制、内容不存在或明确解析失败收据均返回 `EXTRACTION_FAILED`。正常长文即使讨论“正文提取失败”等术语也不能误伤。

### 文件

- 普通非 PDF 附件成功保存即可交付。
- PDF 仅保存附件但没有可用提取正文时失败。
- 明确提取成功但正文为空时失败。

### 音视频

没有可用转写且没有可交付 Markdown 时失败；现有云端转写等待状态继续保持等待，不误报失败。

## 本地旧笔记去重

找到相同 recordId 或 URL 后先检查笔记：

- 失败收据、登录/App 引导、只有原始链接或空正文：不视为已同步，继续正常处理原记录。
- 普通文本记录只要有正文即可；网页需要达到可交付正文门禁；非 PDF 附件嵌入可视为交付证据。
- 不读取目标收集目录之外的笔记。

## 本地恢复队列

在插件设置中保存最多 100 条 `pendingSyncLifecycleAttempts`。每条仅包含：

- `recordId`
- `attemptId`
- `bindingFingerprint`
- `stage`: `processing`、`failed` 或 `committed`
- 安全错误码或安全笔记名
- `createdAt` / `updatedAt`

不保存绑定令牌、正文、URL、本地路径和原始异常。

状态流：

1. 云端 claim 成功后立即记录 `processing`。
2. 本地笔记原子写入后记录 `committed` 和安全笔记名。
3. 明确失败后记录 `failed` 和安全错误码。
4. 完成或失败状态上报成功后删除队列项。
5. 下次同步每个绑定前重放其队列：`committed` 补报成功，`failed` 补报失败，遗留 `processing` 以 `SYNC_INTERRUPTED` 补报失败。
6. 404/405/409 表示记录不存在、旧服务或 attempt 已失效，删除本地队列项；网络错误保留并在下次重试。

## 错误与隐私

- 云端失败请求继续只发送 `status`、`attemptId` 和归一化 `code`。
- 本地恢复队列只保存脱敏绑定指纹。
- 队列持久化失败时当前同步失败关闭，并尝试用当前 attempt 直接上报；不会在未持久化保护时继续写笔记。

## 测试

- 空成功网页、新型今日头条 App 引导、正常短文本、正常长技术文、普通附件、坏 PDF。
- 旧失败占位笔记拒绝去重、正常旧笔记继续去重。
- processing/failed/committed 三类队列重放。
- 成功和失败上报后队列清理；上报网络失败后队列保留。
- 队列归一化上限、无敏感字段、构建资产一致性与既有插件回归。

## 上线与回退

重新构建 1.3.79 本地候选，通过独立审查后只替换指定知识库的四项插件资产。`data.json` 的替换前后 SHA-256、绑定数量和绑定令牌指纹必须完全一致；实际运行后新增的恢复队列属于插件正常配置写入。回退时恢复四项插件资产，保留 `data.json`，旧版本会忽略未知队列字段。
